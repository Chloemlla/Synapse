# 数据保留、取证与法律保留（内部文档）

> 本文件面向**内部**（运维、法务对接、调查响应），不是隐私政策的一部分，不在政策页里引用。
> 用途：把「软删除之后数据还在哪、多久、谁能看、怎么交出去」写成可执行的口径，
> 避免每次被问到时靠人回忆，也避免把「文案说不可恢复、实现是软删除」这条已知差异重复当成新缺陷上报。
>
> 相关编号：RC-11（文案不改的决策）、RC-21（软删除统一）、RC-22（取证保留与调取）、RC-23（本文件）、D7/D8/D9/D10。

## 1. 为什么会有“文案说删了、数据还在”

Owner 于 2026-10-10 明确决策：**前端与法务文案不改**（`PrivacyConsentPanel`、`policyDocument`、
注销通知邮件等一律保持“彻底移除 / 不可恢复”的表述）。同时要求删除改为**软删除**，以便政府机关调查取证。

两者必然不一致。差异已逐条登记在 `docs/audit/10-10.md` RC-23 的四条（E1～E4），本文件负责**内部承接**：
把“实际保留了什么”写清楚，以便面对询问时能如实回答，而不是靠临场解释。

政策正文里已有一个有利锚点：《数据删除的边界》章节写明“账户删除不等于所有相关记录立刻消失”、
“审计、封禁等记录可能按期限继续保留”。保留集合扩大后，E1/E2 与该章节的冲突面比字面上小；
**E3（同意记录）/ E4（注销邮件“已永久删除”）没有锚点**，属 owner 已知悉并接受的告知差异。

## 2. 三类数据与各自命运

| 类别 | 例子 | 账户删除后 | 依据 |
| --- | --- | --- | --- |
| **用户内容与隐私** | API Key、访问令牌、OAuth 身份、工作区、语音项目、工单、偏好、短链 | **物理删除**（现有语义） | 最小化原则；无取证价值 |
| **风控与安全证据** | `account_ip_signals`、`device_trackings`、`security_events`、`auth_sessions`（置撤销）、封禁记录、`blocked_identities` 墓碑 | **保留并打标记**（`subjectDeletedAt` / `deletedAt`） | RC-01/RC-21/RC-22：删除即“洗白”会毁掉风控 |
| **运营数据** | `registration_attempts` 等计数台账 | 按 TTL 到期清理（默认 180 天） | 只用于计数，不承担取证职责 |

**凭据一律清除**（密码材料、TOTP 秘密、恢复码、Passkey 凭据、会话令牌）——
软删除只保留“这个人存在过 + 风险事实”，绝不保留可登录凭据。

## 3. 保留期与依据

- 风控证据：**不设 Mongo TTL**（裁决三），保留期由内部策略决定，默认**长期保留**（账户生命周期 + 调查需要）。
  理由：TTL 索引在数据库内部删除文档，不受应用层 `subjectDeletedAt` 控制，会在法律保留生效前把证据删掉（竞态）。
- 审计日志：默认 60 天 TTL（与政策正文一致），但被 `legal_holds` 命中的对象其相关审计**转存**到不受 TTL 约束的保留集合
  （边界见 RC-35：普通业务审计继续 60 天，只有被 hold 对象转存）。
- 运营计数台账：按各自 TTL 到期清理，清理前**先查 hold**。

## 4. 法律保留（`legal_holds`）操作流程

1. **提出**：法务/合规收到执法或监管调取要求后，记录案件编号（`caseRef`）、范围（`user` / `fingerprint` / `ip`）、
   值、理由、期望保留期。
2. **登记**：`superadmin` 通过管理端（待登记到 `src/config/adminPages.ts`）或运维脚本创建 hold。
   **创建即留痕**（`audit_logs` + `security_events`）：谁、何时、依据什么案件。
3. **生效**：命中 hold 的对象**禁止任何物理删除**——包括管理员硬删、软删除清理任务、TTL 替换后的应用层清理。
   命中时删除动作应失败并告警，而不是静默跳过。
4. **解除**：仅在法务确认后由 `superadmin` 解除，同样留痕。hold 可设 `expiresAt`，到期不自动删除数据，
   只是不再阻止后续清理（是否清理仍由保留策略决定）。

## 5. 取证导出与交付

- **谁能触发**：仅 `superadmin`，且必须过一次**安全会话**（Passkey/TOTP/密码，TTL 3～5 分钟，见 RC-40）。
  建议双人确认（发起 + 批准各一次）。
- **导出什么**：按 `userId` / `ip` / `fingerprint` / 时间窗筛选，覆盖多集合，**固定字段顺序**，
  产出带 **SHA-256 校验和**的归档；校验和随归档一起交付，用于证明“交付件与系统内一致、未被改动”。
- **最小化**：按 hold 的 scope 限定字段，只给调查必要的内容；不附带与案件无关的其它账户数据。
- **交付本身是受审计事件**：谁、何时、什么范围、什么理由、校验和。该审计入**不受 TTL 约束**的集合
  （调查周期常超过 60 天）。
- **加密**：软删除区与导出归档都要加密（复用仓库现有 AES-256-GCM + HKDF 主密钥派生范式）。
