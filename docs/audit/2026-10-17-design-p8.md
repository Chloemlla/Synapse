## 1. 结论

P8/P8b 的主体在 `5d32eeec`（通讯/工具页去任意 hex）、`fac888b8`（env-manager 共享层与邮件/通讯配置域）

## 4. 仍缺项与不修理由

1. **WebhookEventsManager 页面外壳未用 `studioPageClassName`（FD-047）**：当前是
   `max-w-7xl mx-auto px-2 sm:px-4`（`WebhookEventsManager.tsx:812`）。P8 判据未包含 FD-047，
   且 App shell 的 padding 在不同路由下不一致，直接换会改变现有留白；留待 shell 批次统一裁决。
2. **Webhook 自建弹窗未迁 `StudioModal`（FD-044/FD-070）**：已使用 `studioModalOverlayClassName` /
   `studioModalCardClassName` / `studioModalCloseButtonClassName`（`:1376-1390`），视觉合规；
   缺 focus trap/Escape 属于弹窗批次，改动会影响事件测试页面的键盘路径，不在本批扩大范围。
3. **按钮内联 spinner**：`PublicShortLinkCreator.tsx:212`、`ShortLinkManager.tsx:662/691/714/884`、
   `ShortUrlMigrationManager.tsx:168/293` 等是按钮内的小尺寸反馈，替换成 `UnifiedLoadingSpinner`
   会撑破按钮高度；页面级/区域级 loading 已全部走 `StudioLoadingState`。
4. **MailSystemConfigManager 的状态灯 `shadow-[0_0_18px_rgba(...)]`**：语义是「可用/不可用」光晕，
   非禁用色类名；当前闸门的 `arbitrary-color-value` 也不计此类。若后续要严格到「只用 `shadow-sm`」，
   可替换为纯色圆点 + `shadow-sm`。
5. **EmailSender 模板 HTML 内的 `linear-gradient` 与十六进制色**：这些是**邮件正文内容**（随邮件发送、
   由收件端邮件客户端渲染），不是页面 UI 色板；token 化会让邮件在客户端丢失样式，故保留。
   `bg-gradient-to-*` 扫描仅针对 className，模板字符串不在禁用清单内。
6. **SelfContained 镜像组件合并（FD-076 / S5）**：按挂起项 S5 不合并、不删除，避免触碰运行时配置读取链路；
   本批只保证两份实现共用同一展示层（24 个已是委托壳）。
7. **全局基线**：本批未执行 `--update-baseline`。P8 文件自身在全部规则上为 0 命中；
   当前闸门总命中下降主要来自其他并发会话的批次，不能记在本批名下。
8. **env-manager 少量「视觉等价但未取 token」的卡面**：`ProjectLumenConfigSection.tsx:396/416`、
   `ProxycheckConfigSection.tsx:372/398/479`、`CDictDonationConfigSection.tsx:129/172/219` 仍有
   `rounded-2xl border border-slate-200 bg-white/80 …` 手写串。它们与 `studioElevatedPanelClassName`
   的差别是 1px vs 2px 边框、内边距刻度不同，机械替换会改变现有版面；本批只保证颜色/圆角/四态合规，
   换 token 需连带做一次视觉回归，留待 env 面板的专门批次。`EnvRow.tsx` / `InfoBox.tsx` 是表格行与
   语义提示条（无对应 studio token），颜色均已收敛到 slate/amber/emerald。
