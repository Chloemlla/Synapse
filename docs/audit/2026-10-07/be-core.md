## 2. 已核对为干净的区域

- **中间件装配顺序**（`src/app/assembly.ts`）：CSP nonce → helmet → compression（跳过 SSE 与 206/Range）→ CORS 特例 → preBodyParser（IP 封禁 → 全局审计）→ body parser（`__proto__` 快扫 + 仅签名面保留 rawBody）→ WAF → globalCors → isLocalIp → 访问日志 → 路由相位 → 静态/SPA → 错误处理；与 CLAUDE.md 记载一致，未发现新的顺序反转。全局 500 处理器不回显 `error.message`（4xx 才回业务文案）。
- **IP 封禁主链路**（`src/middleware/ipBanCheck.ts`）：除 be-core-01 的 `/0` 边界外，Redis+Mongo 并行竞速、双后端不可用 fail-closed（503 且不写负缓存）、CIDR 缓存、解封清缓存（`clearIPBanCache`）均正确；手工封禁与自动封禁都满足 `violationCount >= MAX_VIOLATIONS` 的精确匹配条件。
- **JWT/会话认证**：`authenticateToken` / `authMiddlewareV2` / `oauthTokenAuth` 三者均走 `assertActiveAuthSession` + `touchAuthSession`（复用同一份会话文档与凭证哈希，PERF-02 形态），禁用/封停校验齐备；`apiDocsAuthGate` 仅回环或显式 `API_DOCS_PUBLIC` 放行且叠加管理员校验；`adminScope` 守卫 fail-closed（403 带 `requiredPages`）。
- **签名类中间件**：`nexaiRequestSignature` / `replayProtection` / `qqGuardSignature` / `lumen/request-signing` 均先验签后消费 nonce，`timingSafeEqual` + 漂移窗口 + nonce 原子申领（E11000 兜底/Redis Lua）齐备；qqGuard 未配 secret 时整树 fail-closed。
- **WAF**（`src/middleware/wafMiddleware.ts`）：ReDoS 已治理（邻接量词改有界中段）、大小写绕过已堵（`charCodeAt` 预检 + 小写化）、query 递归检查数组/嵌套、body 白名单是 relaxed 而非整体跳过；除 be-core-07 的深度截断外未见绕过面。
- **CORS**（`src/middleware/corsMiddleware.ts`）：白名单精确匹配 + 显式通配语法（`*.domain` 要求至少一级子域），`requireAllowedOriginForWrites` 已被管理端配置路由采用；open-CORS 仅限显式声明的端点。
- **CSP 主体**（`src/security/contentSecurityPolicy.ts`）：`script-src` 为 nonce + `wasm-unsafe-eval`（无 unsafe-inline/unsafe-eval），nonce 每响应生成且与 HTML 注入取同一值；阻断页（`ipBlockPage.ts`）全部插值过 `escapeHtml`。
- **SSRF/路径穿越**：`utils/ssrfGuard.ts` 解析后逐地址判定（空解析 fail-closed），`mediaToolHttp` 对 bili 下载做「域名白名单 + `validatePublicUrl` DNS 复核」双闸；`relInside`/`relInsideRoot` 在文件浏览/删除/转写全链守住 workRoot；`tts.assetAccess` 的文件名白名单 + 路径守界 + HMAC 签名 + `timingSafeEqual` 齐备。
- **命令执行**：`biliYtDlp`/`runtime` 全部走 `spawn`/`spawnSync`/`execFileSync` 的 argv 形式（无 shell 拼接），yt-dlp/ffprobe 路径仅管理员可配；日志前 `redactArgs`/`maskStreamUrl` 剥签名参数。
- **TTS 额度/队列/存储**：quota 走事务 + taskId 唯一索引，日键已是 Asia/Shanghai（B2-06 已修）；job 租约 + owner 条件终态写入 + 最大尝试死信齐备；history 用户写操作把 owner 条件写进查询过滤器（无 TOCTOU），软删记录不参与去重。
- **媒体工具任务层**：`mediaJobRunner` 写盘串链（先发的快照不会盖掉终态）、转写正文先于指针入库、双态 store 接口一致；`transcribeUserHttp` 按 `scope+ownerId` 复核归属、产物下载限定任务登记且落在用户目录内的文件。

## 3. 存疑 / 需人工确认

- **历史遗留（GB-02，2026-10-04 登记待决策，仍未修）**：`/api/tts` 在 preDocs 相位挂载（`src/routes/routeModules/preDocsModules.ts:9`），IP 验证闸门 `ipVerificationMiddleware` 在 preTamper 相位才挂（`src/routes/routeModules/preTamperModules.ts:143`），TTS/LibreChat 路由整段绕开首访验证闸门。处置需 owner 定策略（前置会打断不携带指纹头的 API Key/Bearer 客户端），本轮按「登记待决策」原样保留，不重复记为缺陷。
- **body parser 的 `__proto__` 快扫可被 Unicode 转义绕过**（`src/app/assembly.ts:270-276`）：`"\u005f\u005fproto\u005f\u005f"` 不经 `buf.includes('"__proto__"')` 命中，但 `JSON.parse` 会还原成 `__proto__` 自有键。当前全仓未发现 merge/assign 型 sink（`lodash` 未被 src 引用），污染无法兑现成实质危害，属纵深防御层的已知弱项而非可利用漏洞；如要堵，用 `JSON.parse` 的 reviver 或解析后做一层键名扫描，而不是 Buffer 字节匹配。
- **`optionalAuthenticateToken` 不校验 `disabled`/封停/会话撤销**（`src/middleware/optionalAuthenticateToken.ts`）：注释声明是「游客语义」的刻意取舍，且真正放宽闸门的消费方（`optionalAdminAuth`）已自行补 `assertActiveAuthSession` + 状态校验。需确认没有其它消费方把 `req.user` 的存在当成「已校验的活跃身份」用（抽查的 TTS 链路经 `apiKeyAuth(required)` 收口，无此问题）。
- **`lumen` 设备绑定可自助覆盖**：`User.deviceInstallationId` 由 `/api/lumen/devices/register` 写入，老设备随即被 `requireDeviceSecurity` 拒之门外。写路径在 routes/services（本组范围外），未深审其是否有二次确认；自查后果为可恢复的误锁（重新注册即恢复），风险低。
