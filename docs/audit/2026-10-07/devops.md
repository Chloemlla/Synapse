## 2. 已核对为干净的区域

- **auto-merge 门禁链**：`scripts/auto-merge.js` 对「skipped ≠ 通过」单独记账、required check 逐项对账、merge 绑定 SHA 双评估，未发现「跳过被当通过」；`docker.yml` 的 publish/deploy 凭 actor 白名单 + `npm(deps):` 排除，与 AGENTS.md §7 流程一致。
- **部署脚本日志脱敏**：`scripts/deploy_image.js` 的 `sanitizeDeployLogMessage` 覆盖私钥块、`PASSWORD/TOKEN/SECRET/API_KEY` 赋值与 `process.env` 快照；`logSensitive` 对 stdout/stderr 统一 `[sensitive output redacted]`，未见凭据明文入 CI 日志。
- **Dockerfile 凭据不进镜像**：生产 stage 只 `pnpm install --prod` + 删 npm/corepack/pnpm/yarn 二进制，`GIT_SHA` 经 build-arg 注入而非 `.git`，`.dockerignore` 排除 `.env*`/`secrets/`/`data/`，未见凭据 COPY 进镜像。
- **健康检查**：Dockerfile `HEALTHCHECK` 打 `/health` 且端口取 `PORT` 环境变量；`docker-compose.yml` healthcheck 与之一致；tsc.yml 的 mongo service 有 `--health-cmd`，nightly 的 mongo 起副本集有 PRIMARY 探测循环。
- **CI 脚本引用存在性**：`package.json` 中 CI 实际用到的 `generate:*`、`check:*`、`smoke:obfuscated`、`test:ci`、`test:nightly*`、`test:integration:mongo`、`test:browser` 指向的脚本全部存在（逐一 `[ -e ]` 验证）；除 devops-04/10/13 外无死链。

- **nightly-test-matrix.yml 两套件 10/10 连败的根因**：本审计只读确认了**现象层根因**——两套件全部 10 个用例在 `beforeAll → connectMongo()` 抛 `MongooseServerSelectionError: Missing required sub-document 'driver' in the client metadata document`（`gh run view 37529016437` 原文，mongoose 9.10.3 / mongodb driver 7.7.0 / CI 服务容器 `mongo:8`）。**与「测试自身前置条件」无关**：policyApi 仅 `connectMongo + deleteMany`、logshare 仅 `connectMongo`，均不依赖副本集/事务/固定数据。**真正分歧点**在 driver 与 server 的握手元数据校验：`quality-guardrails.yml` 的 `mongo-replica` job 用 `directConnection=true&replicaSet=rs0` 连**同一镜像** `mongo:8` 却 success（run 37245521908），而 nightly 直连（无 `replicaSet` 参数）失败。疑似 mongodb driver 7.7.0 对「直连副本集 mongod」的 client metadata 校验与该 `mongo:8` 镜像（digest `sha256:d731d77b…`）实际 server 版本不兼容，但**无法在只读约束下复现/二分**（禁本地构建）。建议人工：给 nightly 的 `MONGO_URI` 加 `?replicaSet=rs0&directConnection=true` 对齐 quality-guardrails，若转绿即坐实「直连模式 + 该 mongo:8 小版本」的组合问题；同时把 `mongo:8` 钉到小版本（如 `mongo:8.2.5`）消除滚动镜像变量。
- **`docker-compose.yml` 的 `mem_limit`/`cpus` 与新版 compose 的 `deploy.resources` 语法并存**，老字段在 compose v2 已弱化但当前可读，未判缺陷，登记。
- **`scripts/fix-dependabot-alerts.js:1002`** 用 `pnpm up --latest --lockfile-only` 升级依赖，`--latest` 会越过 `package.json` 的 `^` 上限取最新 major，与 AGENTS.md §7「`repair-lockfiles` 只跑 `install --lockfile-only`，不顺手升级」的表述存在张力；该路径仅在 `fix-alerts` 分支触发，需人工确认是否为有意设计。
