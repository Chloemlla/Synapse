## 3. 存疑 / 需人工确认

1. **public OAuth 客户端是否应继续收 refresh_token**（be-services-2-14）：PiliPlus 是生产在用的 public 客户端，若其移动端依赖 refresh 流程则属产品契约而非缺陷；需 owner 确认后再决定「按 RFC 8252 收紧」还是「注释声明有意为之」。
2. **redisService 的 `enabled` 语义**（be-services-2-23）：若管理端状态卡确实直读 `enabled` 当「Redis 健康」，则挂掉后仍绿是误导；需确认前端实际读的字段后再定是改语义还是改前端。
3. **md4→md5 静默替换**（be-services-2-15）：若外部集成方已按「md4 请求=MD5 结果」的行为对接（历史行为），改成显式失败会破坏其契约；建议先在响应里加 `actualAlgorithm` 字段过渡一个版本再收紧。
4. **userService 级联删除在事务内 `Promise.all` 并行 30 个集合**：MongoDB 驱动对同 session 并行操作的排队语义在文档上不明确（WiredTiger 单 session 通常串行化，但驱动层行为未保证）；测试环境（`src/tests/setup.ts` 默认 `mongodb://127.0.0.1:27017/tts-test` 单节点）会不会在 `deleteUser` 路径抛 `IllegalOperation: Transaction numbers are only allowed on a replica set member or mongos`，取决于 CI 的 Mongo 形态——Quality Guardrails 有 replica 集成 job，Node Verification 的单测若走单节点则会暴露。本条登记为**需 CI 观测的隐患**，未列入主表（证据不足以断言线上必现）。
5. **`TTS_REQUIRE_POLICY_CONSENT` / `AUTH_REQUIRE_POLICY_CONSENT` 默认值不对称**：前者默认 false（只认显式 true），后者生产默认 true；若属有意（注册必须同意、TTS 可单独开关）则无需动，登记供 owner 核对口径。
