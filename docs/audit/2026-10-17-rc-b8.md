## 3. RC-35：独立不设 TTL 的取证审计集合

- 模型：`src/models/forensicAuditModel.ts`
  - `forensic_audit_logs`：`eventId`、`action`、`actor`、`caseRef`、`scope/subjectValue`、`reason`、`exportRequestId`、`detail`、请求元数据、`createdAt`；**无 TTL**。
  - `forensic_export_requests`：双人确认的持久化载体（发起人、批准人、案件、范围、时间窗、状态、行数、校验和）；**无 TTL**。
- 服务：`src/services/forensicAuditService.ts`
  - `writeForensicAudit`：直接 `create`，不经过批量缓冲（法律事件不能因进程崩溃丢最后一批）。
  - `recordForensicEvent`：双写 `audit_logs`（普通 60 天）与 `forensic_audit_logs`（永久），任一失败都 `logger.error`，不静默。
  - `listForensicAuditPage`：`(createdAt, _id)` 游标分页，limit ≤ 200。
- 边界：普通业务审计仍是 `audit_logs` 60 天 TTL；本轮**没有**改动 `AuditLogModel`。
- 已知缺口（如实登记）：hold 建立**之前**已超过 60 天的普通审计无法追回；hold 建立后新产生的审计仍会先落 60 天集合。若需“命中 hold 即把历史审计转存永久集合”，需另加一次快照任务（建议作为 RC-35 后续，本轮未实现）。

## 4. RC-58：导出游标/流式与行数硬顶

导出实现位于 `src/services/forensicAuditService.ts`：

1. **双重行数闸门**：发起申请时 `countForensicExportRows` + `assertWithinExportCap`；下载前再算一次（防止申请后新增数据）。超限抛 `ForensicExportLimitError`：
   - HTTP `413`
   - `code: "EXPORT_LIMIT_EXCEEDED"`
   - `truncated: false`
   - 文案明确「未导出任何数据」，**不是截断**。
2. **流式**：`streamForensicExport` 按 `_id > lastId` 游标每页 500 行读取，NDJSON 逐行 `res.write`，带 backpressure（`drain`）与客户端中断处理。
3. **硬顶**：`FORENSIC_EXPORT_MAX_ROWS = 20_000`。计数后若仍有并发新增导致超限，直接中断连接，绝不静默少写几行。
4. **校验和**：SHA-256 覆盖全部数据行（不含 manifest 行）；manifest 作为 NDJSON 最后一行随档交付，并回写 `forensic_export_requests.checksum/rowCount`，同时写 `forensic_export.download` 取证事件。
5. **固定字段顺序**：每个集合有显式 `fields` 白名单，输出按白名单顺序组装；不含密码/令牌/恢复码/Passkey 凭据。
6. **列表端点**：hold 列表与取证审计列表均为游标分页（≤200/页），不接受整表拉取。

导出源（按 scope）：

| scope | 集合 |
| --- | --- |
| user | `user_datas`（最小字段）、`SecurityEvent.collection.name`、`DeviceTracking.collection.name`、`DeviceFingerprint.collection.name`、`AccountIpSignal.collection.name`、`AuditLogModel.collection.name`、`ForensicAuditLogModel.collection.name` |
| ip | `SecurityEvent.collection.name`、`DeviceTracking.collection.name`、`AccountIpSignal.collection.name`、`proxycheck_risk_cache`、`AuditLogModel.collection.name`、`ForensicAuditLogModel.collection.name` |
| fingerprint | `SecurityEvent.collection.name`、`DeviceTracking.collection.name`、`DeviceFingerprint.collection.name`、`ForensicAuditLogModel.collection.name` |

前置条件：导出对象必须有**生效中的 legal hold**，否则 403 `FORENSIC_EXPORT_HOLD_REQUIRED`；hold 状态不可判定时 503 `FORENSIC_EXPORT_HOLD_UNKNOWN`（fail-closed）。

### 6.9 加密（RC-22.7）的当前口径

本轮导出为 NDJSON 明文（TLS 传输），**没有**做 AES-256-GCM 归档加密。D10 只要求“带校验和归档”；若 owner 要求静态加密交付件，建议在 `forensicAuditService.streamForensicExport` 外再包一层流式 AES-GCM（复用 `utils/passwordSecurity` 的 HKDF 主密钥派生），并同步调整“校验和先对明文还是密文”的交付说明。该项挂起。
