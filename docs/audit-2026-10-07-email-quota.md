### EQ-01 工作空间通知和邮箱变更仍隐式共享验证码配额

- 位置：`src/controllers/workspaceController.ts:230,327`；`src/routes/admin/profile.ts:418`。
- 类型：业务策略。
- 根因：邀请/接受通知显式 `checkQuota:true`，邮箱变更使用默认 `true`；前者能够消耗收件人的 verification 桶并阻止后者。
- 修法：通知与账号邮件不参与用户手动发信日额；换邮箱主动验证码显式 transactional 用途，邀请保持通知用途并尊重退订。
- 回归：由 emailSender 的不扣日额/用途测试覆盖，静态核对所有显式 true 调用。

### EQ-02 对外路由静默截断收件人与批量消息

- 位置：`src/routes/outemailRoutes.ts:127-191,212-222`。
- 类型：输入契约与数据丢失。
- 根因：单发数组仅使用首个地址；批量先 filter 再 slice(0,100)，合法请求中混入无效条目或超过100条仍返回整体成功，未处理项被丢弃。单发正则还拒绝合法的 `+` 地址。
- 修法：单发接受字符串或单元素数组，多地址明确要求批量入口；批量全量验证大小、字段类型与每一个收件人，不静默过滤。保留兼容单元素数组。配额/冷却/发送失败由稳定 code 和 HTTP 状态表达。
- 回归：多地址、混合无效批次、超大批次均 400 且不调用服务；合法带 `+` 邮箱、单元素数组可发送；429带等待时间，503与额度耗尽可区分。

### EQ-03 邮箱变更冷却与失败清理不具备请求归属

- 位置：`src/services/profileUpdateVerificationService.ts:319-437`；`src/routes/admin/profile.ts:412-426`。
- 类型：防刷、并发、生命周期。
- 根因：只对相同新邮箱冷却，换地址可绕过；创建/失败次数更新是共享存储 get→set，多请求可覆盖；老请求发送失败按 userId 无条件清理，可能删除后发的新码；错误校验可在 await 间覆盖新挑战。
- 修法：同用户邮箱变更状态操作由共享锁串行；冷却与目标邮箱无关；挑战有唯一 ID，发送失败只清自己的挑战；429携带服务器剩余等待秒数。保留现有共享存储降级边界，不扩展到会话撤销机制。
- 回归：并发创建仅一个成功；切换邮箱仍冷却；旧挑战失败不能清除新挑战；并行错码累计不丢失。

### EQ-04 后端接受脱敏密钥回写

- 位置：`src/services/runtimeConfigService.ts:2464-2485`，关联 FE-02。
- 类型：配置完整性。
- 根因：读取时 maskSecret，写入时所有非空值都被当作新密钥；旧前端只改配额也能把真实值替换成掩码。
- 修法：前端仅提交新输入；后端识别自身脱敏占位符并保留真实值，支持旧页面；三项邮件凭据统一处理。
- 回归：读→仅改配额→写保留三项凭据，明确新值仍可更新。

## 期望行为

账号主动验证、注册、找回和换邮箱不受手动发信日配额限制；仍受按地址/用户短时冷却、CAPTCHA 和 IP 速率限制。普通管理员手动发信按用户统一预算，对外发信使用独立公共预算；两者以实际接受的收件人数结算，不按切换域名或发送方式另开额度。
