## 1. 背景与现状

2026-10-02 的一轮优化已经补齐了工单系统的基础骨架：分页摘要、关键词/日期筛选、未读、
受理人、内部备注、批量改状态、概览条、快捷回复、附件与附件链接、深链 `?ticket=<id>`。
本轮不再重复这些能力，而是解决「**上一轮之后仍然让用户和客服多花时间**」的问题。

### 1.1 现状盘点（代码事实）

| 区域 | 现状 | 问题 |
| --- | --- | --- |
| 用户列表 | 只按 `updatedAt` 倒序分页，无筛选 | 工单多了以后找不到历史工单；无法只看「处理中」 |
| 创建工单 | 7 组字段一次性平铺 | 首次提交认知负担高；`TICKET_CREATE_TEMPLATES` 已定义但**从未被使用** |
| 创建草稿 | 只有回复框有草稿 | 长描述切页/误触后丢失 |
| 会话区 | 每条消息独立时间戳，无日期分隔 | 长对话难以定位「哪一天」；新消息到达时无条件滚到底 |
| 消息操作 | 编辑/删除按钮 hover 才出现，极小 | 触屏与键盘用户几乎不可用；编辑框在浅色气泡上是**白字浅底**，不可读 |
| 解决后 | 只剩回复框 | 用户没有「确认解决」的反馈出口；客服看不到满意度 |
| 管理概览 | 7 张卡：待回复/逾期/四状态/总数 | 缺少「我的待办、未分配、今日新增/解决、平均首响、满意度」 |
| 管理筛选 | 状态/优先级/分类/类型/服务/受理人/日期/未读/待回复 | 无「快捷视图」；筛选条件刷新即丢，链接无法分享 |
| 批量操作 | 仅「标记已解决 / 关闭」 | 不能批量认领、转派、改优先级/分类 |
| 详情头部 | 状态/优先级/分类/认领/复制链接 | 无上一条/下一条；无 SLA 与满意度提示 |
| 处理过程 | 只有消息 | 状态、受理人、优先级变更无记录，客服交接靠回忆 |
| 指标 | 只有存量计数 | 无首响时长、解决量、满意度，无法判断支持质量 |
| 附件设置 | 超管的附件开关卡片常驻工单台顶部 | 高频操作页面里常驻低频设置，挤占首屏 |
| 无读提示 | 页面顶部有未读数 | 浏览器标签页不提示，切到别的标签会错过回复 |

### 1.2 本轮不做什么（Non-goals）

- 不新增第三方依赖、不引入新的 UI 组件库、不改路由前缀。
- 不做多语言、不做工单转派给外部供应商、不做工单合并/拆分。
- 不改现有权限模型：普通管理员仍不可读工单原文；`superadmin` 仍是唯一客服写角色。
- 不把工单正文做成全文索引（本轮只在现有字段上做安全正则搜索）。
- 不做实时协同编辑、不做消息撤回。

## 2. 目标与验收指标

### 2.1 用户目标

1. **更快找到工单**：任意历史工单在 15 秒内可被定位（搜索 + 状态筛选）。
2. **更少提交失败**：首次提交字段填写时间下降，长文不丢失。
3. **更清楚地知道「现在到哪一步」**：状态、处理记录、未读、日期分隔一眼可见。
4. **有反馈出口**：问题解决后可一键评价，评价可修改。

### 2.2 客服目标

1. **一屏决定先做哪张单**：我的待办 / 未分配 / 逾期 / 待回复直接可见可点。
2. **少切页面**：批量认领、改优先级/分类、解决/关闭在列表内完成。
3. **交接不留口述**：每张单有可追溯的处理记录与首响/解决时间。
4. **不误操作**：关闭/删除等破坏性动作有确认；编辑框可读；状态变更可回退。

### 2.3 验收指标（上线后可观测）

| 指标 | 现状 | 目标 |
| --- | --- | --- |
| 工单列表筛选使用率 | 无用户筛选 | ≥ 25% 的活跃用户至少使用一次搜索或状态筛选 |
| 创建表单放弃率（打开未提交） | 未统计 | 相对本轮前下降 ≥ 20% |
| 平均首次响应时长 | 未统计 | 可统计，并按周观察 |
| 解决工单评价率 | 0 | ≥ 15% 的已解决工单收到评价 |
| 客服批量操作使用率 | 仅状态 | 批量认领/改优先级被实际使用 |

> 指标本身依赖后端新增字段；本轮先把「能测」做出来，数值目标在后续迭代校准。

## 3. 用户画像与关键场景

### 3.1 用户（工单属主）

- **首次求助**：不知道要填什么，希望有「无法登录 / 合成失败 / 额度异常」等模板。
- **补充信息**：在长对话里找到上次客服要的截图位置，接着回复。
- **回访**：从邮件/通知点进来，深链直达某张单；看到未读与处理进度。
- **结案**：问题解决后确认关闭，并愿意给一个 1–5 星评价。

### 3.2 客服（superadmin）

- **早班分诊**：打开工单台，先看「未分配 / 我的待办 / 逾期」，批量认领。
- **处理中**：看处理记录确认上一班做到哪一步；用内部备注记录排查；用快捷回复。
- **交接**：按「我的待办」筛选，确认每张单的 SLA 与最后一条消息。
- **质检**：按「满意度 ≤2 星」筛出需要回访的工单。

### 3.3 只读管理员（admin）

- 仍不可读写工单原文；本轮不改变该行为。管理端入口对只读管理员保持 403 文案。

## 5. 功能需求

### 5.1 用户端：查找与列表（P0）

- **U-01 搜索**：标题/描述关键词，350ms 防抖；输入框占位「搜索标题或描述」。
- **U-02 状态筛选**：全部 / 待处理 / 处理中 / 已解决 / 已关闭，胶囊按钮；单选。
- **U-03 排序**：最近更新（默认）/ 最新创建 / 最久未更新。
- **U-04 结果计数**：显示「已加载 N 条 / 共 M 条」，筛选生效时显示「筛选后」。
- **U-05 空结果**：区分「还没有工单」与「没有符合条件的工单」；后者提供「清空筛选」按钮和「发起新工单」按钮。
- **U-06 刷新**：保留当前筛选与选中工单；失败时显示 inline 重试。
- **U-07 加载更多**：保留已加载条数，不清空选中详情。

**后端**：`GET /api/tickets` 接受 `q`、`status`、`sort`；校验与转义规则与 `/admin/all` 一致。

### 5.2 用户端：创建工单（P0）

- **U-08 模板入口**：标题下方展示 5 个模板胶囊（无法登录 / 语音合成失败 / 额度计费异常 / 第三方绑定 / 功能建议）。
  - 点击后填充标题、分类、描述骨架。
  - 若标题或描述已有内容，先弹确认「套用模板会覆盖已填写的标题和描述」。
- **U-09 分层表单**：
  - 默认展示：模板、标题、问题分类、详细描述、紧急程度、提交按钮。
  - 「更多信息（可选）」折叠区：工单类型、相关服务、服务说明/任务 ID、联系邮箱、关联工单、附件。
  - 折叠区显示已填写的摘要（如「相关服务：语音合成 · 附件 2 个」），不让可选信息悄无声息。
- **U-10 草稿**：标题/描述/所有字段持久化到 `localStorage`（key `synapse:ticket-create-draft`），
  重新进入时恢复并提示「已恢复上次未提交的草稿 / 丢弃草稿」。
- **U-11 提交反馈**：提交中禁用按钮；成功后清空草稿；失败保留全部输入与附件选择。

### 5.3 用户端：会话可读性（P0）

- **U-12 日期分隔**：相邻消息跨自然日时插入「今天 / 昨天 / 2026年10月17日」分隔条，`role="separator"`。
- **U-13 时间语义**：每条消息用 `<time dateTime>`，显示相对时间（刚刚/N 分钟前/N 小时前/日期），
  `title` 给完整时间。
- **U-14 新消息提示**：用户向上翻阅时收到新消息，不强制滚动，显示浮动的「有新消息 · 回到底部」。
  原本在底部时继续自动滚动。
- **U-15 读屏通知**：新消息到达时通过 `aria-live="polite"` 的隐藏区域播报「收到新消息」。
- **U-16 消息操作**：复制整条消息；管理员的编辑/删除入口在 hover 与键盘 focus 时都可到达；
  按钮有 `aria-label`。编辑框固定为白底深色字，浅色/深色气泡上都可读。

### 5.4 用户端：满意度（P0）

- **U-17 评价卡**：工单状态为 `resolved` 或 `closed` 且当前用户是属主时，在回复框上方显示。
  - 未评价：1–5 星单选（`role="radiogroup"`），可选文本评价（≤500 字），提交按钮。
  - 已评价：显示星级、评价内容、评价时间；提供「修改评价」。
  - 评价只对属主开放；管理员在详情头部看到只读星级。
- **U-18 评价接口**：`POST /api/tickets/:id/csat`，body `{ rating: 1..5, comment?: string }`。
  - 仅属主；状态必须是 `resolved` 或 `closed`；重复提交视为修改。
  - 返回更新后的工单视图；写 WS 与管理端可见字段。
  - 评价内容进入工单视图（属主与 superadmin 可见），列表摘要只带 `csatRating`。

### 5.5 管理端：分诊工作台（P0）

- **A-01 快捷视图**：全部 / 我的待办 / 未分配 / 待回复 / 逾期 / 低满意度。
  - 我的待办：`assignee=me` 且尾消息为用户（`awaitingReply=1`）。
  - 未分配：`assignee=unassigned` 且未关闭。
  - 待回复：`awaitingReply=1`。
  - 逾期：`awaitingReply=1&sort=oldest`，列表显示逾期徽标。
  - 低满意度：`csat=low`（1–2 星）。
- **A-02 概览条**：新增 我的待办、未分配、今日新增、今日解决、平均首响、满意度；
  保留 待回复、逾期、四状态、总数。点击卡片应用对应筛选；当前视图高亮。
- **A-03 筛选持久化**：筛选条件写入 URL（`q/status/priority/category/type/service/assignee/awaitingReply/unread/csat/sort/from/to/limit`）。
  刷新与复制链接都恢复同一视图。写入用 `replaceState`，不产生逐次筛选历史 —— 浏览器后退回到上一个页面，
  而不是在几十个筛选状态之间倒带（关键词每敲一次都压一条历史会让后退变得不可用）。
- **A-04 批量操作**：勾选后批量条支持：
  - 认领给我 / 取消分配
  - 改优先级（低/一般/紧急）
  - 改分类（5 类）
  - 标记已解决 / 关闭 / 重新打开
  - 全选本页 / 退出批量
  - 操作前确认；完成后显示「已更新 N 张（其中 M 张无变化）」。
- **A-05 列表信息**：每行显示 SLA 逾期、满意度星级（≤2 星用 rose）、未读、最后一条来源、受理人。
- **A-06 下一条/上一条**：详情头部可顺序切换当前筛选结果中的工单；到头/到尾时按钮禁用。
- **A-07 详情 SLA**：`resolved` 前显示「已等待 N 小时」；超过 24h 且尾消息为用户时显示「逾期」。
- **A-08 处理记录**：状态/优先级/分类/受理人/满意度变更形成时间线，默认折叠；管理员可展开全部，
  用户端只显示脱敏后的操作者（「客服」），不泄露客服账号名。
- **A-09 附件设置降噪**：附件上传开关与授权名单移入「管理设置」折叠区，默认收起；
  摘要行显示「普通用户上传：关闭 · 单独授权 3 人」；读取失败提供重试。
- **A-10 只读管理员**：仍显示只读提示与 403 文案；不渲染批量条与写控件。

### 5.6 共享：导航与键盘（P1）

- **S-01 标签页未读**：未读数 >0 时 `document.title = "（N）支持中心 - Synapse"`，离开页面恢复原标题。
- **S-02 键盘导航**：焦点不在输入框/文本域/下拉时，`j`/`k` 在列表中上下移动并打开；
  手机端 `Esc` 从详情返回列表。
- **S-03 深链**：`?ticket=<id>` 与筛选参数共存；打开工单不丢筛选；复制链接包含当前筛选。
- **S-04 专注模式**：保留现有 localStorage 偏好；筛选变化不重置专注模式。

## 6. 后端设计

### 6.1 数据模型（`src/models/ticketModel.ts`）

新增字段（全部向后兼容，老文档视图层补默认值）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `firstResponseAt` | `Date \| null` | 首次非属主公开回复（AI 或人工）时间；用于平均首响 |
| `resolvedAt` | `Date \| null` | 最近一次进入 resolved/closed 的时间；重新打开时清空 |
| `csatRating` | `number \| null` | 1–5，属主评价 |
| `csatComment` | `string \| null` | ≤500 字，可空 |
| `csatSubmittedAt` | `Date \| null` | 评价/修改时间 |
| `events` | `TicketEvent[]` | 处理记录，最多保留最近 100 条（`$slice: -100`） |

`TicketEvent`：

```ts
{
  type: "created" | "status" | "priority" | "category" | "assignee" | "type" | "service" | "csat";
  actorId?: string;
  actorName?: string;
  actorRole: "user" | "admin" | "superadmin" | "ai" | "system";
  from?: string | null;
  to?: string | null;
  note?: string | null;
  createdAt: Date;
}
```

新增索引：`{ assigneeId: 1, updatedAt: -1 }`、`{ status: 1, updatedAt: -1 }`（分诊筛选 + 排序）。

### 6.2 接口变更

#### `GET /api/tickets`

新增 query：

| 参数 | 规则 |
| --- | --- |
| `q` | ≤120 字，正则转义；匹配 title/description（用户只看自己的工单） |
| `status` | `open/in-progress/resolved/closed`，非法忽略 |
| `sort` | `updated`（默认）/`created`/`oldest` |

#### `GET /api/tickets/admin/all`

- `q` 追加：合法 ObjectId 时匹配 `_id`；匹配 `assigneeName`。
- 新增 `csat=low`：`csatRating` 存在且 ≤2。
- `assignee=me` 继续使用当前登录管理员 ID。

#### `PATCH /api/tickets/admin/bulk/status`

保留原路径以兼容前端旧调用；请求体扩展为：

```json
{
  "ids": ["..."],
  "status": "resolved",
  "priority": "high",
  "category": "bug",
  "assignee": "me"
}
```

- 至少提供一个可更新字段；`ids` 1–100。
- `assignee` 支持 `me` / `none` / 合法 userId。
- 用 `bulkWrite` 逐条写入 `$set` + `$push` 事件；只对真正变化的字段处理。
- 状态变化才发状态邮件；所有变化都发 WS 更新。
- 返回 `{ success, updated, matched, status?, priority?, category?, assignee? }`。

#### `POST /api/tickets/:id/csat`

- 限流 `ticketWriteLimiter`；路由级审计 `ticket.csatSubmit`。
- 仅属主；`resolved`/`closed`；`rating` 整数 1–5；`comment` trim ≤500。
- 更新 CSAT 字段、追加 `csat` 事件、WS 通知、返回视图。

#### `GET /api/tickets/admin/stats`

新增字段：

```ts
{
  awaitingMine: number;
  mineOpen: number;
  unassigned: number;
  createdToday: number;
  resolvedToday: number;
  avgFirstResponseHours: number; // 最近 30 天，保留 2 位
  csatAverage: number | null;    // 1 位小数
  csatCount: number;
}
```

### 6.3 首次响应与解决时间

- 属主发言不算首响；内部备注不算首响。
- AI 回复、人工回复（非属主公开消息）首次出现时写 `firstResponseAt`（仅当为空）。
- 状态进入 `resolved`/`closed` 时写 `resolvedAt`（仅当为空）；回到 `open`/`in-progress` 时清空。
- 批量操作与单条操作共用同一套判定。

### 6.4 视图与隐私

- `toTicketView`：
  - 属主视角（`includeInternal !== true`）把管理员/超管角色的 `actorName` 脱敏为「客服」，
    `actorId` 不下发；系统/自己保留原值。
  - `csatComment` 只下发给属主与 superadmin；列表摘要只带 `csatRating`。
- `toTicketSummary`：增加 `csatRating`；不带 `events`、`csatComment`、`firstResponseAt`。
- WS `notifyTicketUpdate` 继续走 `toTicketView(ticket, false)`，所以事件脱敏自动生效；
  管理员收到 `ticket:update` 后前端本来就会重新拉详情。
- 隐私数据地图 `tickets` 数据集补 `csatRating/csatComment/csatSubmittedAt/events` 字段说明与变更记录。

## 7. 交互与视觉规范

### 7.1 复用基线

- 页面壳：`studioPageClassName` / `studioMainSurfaceClassName` / `studioPanelClassName`。
- 按钮：`studioPrimaryButtonClassName`（主操作）/ `studioGhostButtonClassName`（次级）/ `studioDangerButtonClassName`（破坏）。
- 字段：`studioFieldClassName` / `studioTextareaClassName`。
- 徽标/胶囊：`studioBadgeClassName` / `studioPillClassName`。
- 四态/弹窗：`StudioEmptyState` / `StudioErrorState` / `StudioLoadingState` / `StudioModal`（来自 `studioFeedback`）。
- 禁止：indigo/purple/fuchsia/pink、gray/zinc/neutral/stone、red/green/yellow、任意 hex、非 `rounded-2xl/full` 圆角。
- 圆角：卡片/面板/按钮/输入 `rounded-2xl`；胶囊/徽标 `rounded-full`。

### 7.2 状态色

| 语义 | 色 |
| --- | --- |
| 主操作 / 选中 | `slate-900` |
| 信息 / 待处理 | `sky` / `blue` |
| 处理中 / 一般 | `amber` |
| 成功 / 已解决 | `emerald` |
| 危险 / 逾期 / 低满意度 | `rose` |
| 内部备注 | `violet`（既有口径，不扩散到其他语义） |
| 中性 | `slate-50…950` |

### 7.3 响应式

- `<768px`：列表/详情单栏；筛选与统计横滑；批量条吸底；回复框吸底。
- `≥768px`：双栏；列表独立滚动；详情头部不换行溢出（文本节点 `min-w-0`，按钮 `shrink-0`）。
- `≥1536px`：消息气泡最大宽度收窄到 70%，避免长行。

### 7.4 可达性

- 所有图标按钮有 `aria-label`；批量勾选有 `aria-pressed`。
- 星级评价是 radio 语义，方向键可切换，`aria-checked` 正确。
- 日期分隔 `role="separator"`；消息区 `aria-live="polite"`。
- 焦点环使用 `focus-visible:ring-2 ring-slate-400`。
- 颜色不是唯一信息载体：逾期/低满意度同时有文字徽标。

### 7.5 文案

- 统一中文；专业术语首次出现给解释（如「SLA：首次响应时限」）。
- 不向用户暴露内部实现（provider、endpoint、异常类型）；管理员诊断仍收在「详情」。
- 破坏性操作确认文案说明后果与可逆性。

## 8. 异常与边界

| 场景 | 行为 |
| --- | --- |
| 用户筛选无结果 | 空态 + 清空筛选 + 发起新工单 |
| 深链工单无权限/不存在 | 保留列表，toast 说明；不白屏 |
| 新消息到达时用户正在翻阅 | 不强制滚动，显示回到底部按钮 |
| CSAT 提交失败 | 保留评分与评论，toast 报错，可重试 |
| 批量操作部分失败 | 显示成功/失败计数；刷新列表以服务端为准 |
| 附件设置读取失败 | 折叠区内显示错误 + 重试，不假装「关闭」 |
| 管理员正在编辑消息时有人追加消息 | 仍按消息索引提交；失败提示刷新（既有行为） |
| 只读管理员 | 只读提示；不显示批量条、写控件 |
| 关闭的工单 | 不可回复/上传/改附件链接；可查看处理记录与满意度 |

## 10. 验收标准

### 10.1 功能

1. 用户可按关键词与状态筛选自己的工单，刷新后筛选保留在 URL。
2. 模板点击可填充表单；已有内容时先确认；草稿可恢复与丢弃。
3. 会话跨天有日期分隔；向上翻阅时新消息不强制滚动；回到底部按钮可用。
4. 已解决工单的属主可提交/修改 1–5 星评价；管理员能看到星级。
5. 管理员可用 6 个快捷视图；概览卡点击即筛选；筛选可分享。
6. 批量条可认领、取消分配、改优先级、改分类、解决、关闭；结果计数正确。
7. 详情可上一条/下一条切换；处理记录显示状态/受理人/优先级/分类/满意度变更。
8. 附件设置默认折叠，读取失败可重试。
9. 只读管理员看不到写控件，且服务端仍拒绝写入。

### 10.2 安全与一致性

1. 内部备注、AI 诊断、CSAT 评论不泄露给非属主/非超管。
2. 事件中的管理员姓名对属主脱敏为「客服」。
3. 普通管理员仍无法读取他人工单原文。
4. 批量接口只接受 1–100 个合法 ObjectId，字段白名单校验。
5. 新增路由有认证 + 限流 + 审计；不新增无认证入口。

### 10.3 质量闸门

1. `check:ts-file-size`：`TicketSystem.tsx` 不因本轮继续膨胀（通过抽取组件回落）；`ticketController.ts` 不超过 1500 行。
2. `check:frontend-design-language`：不新增任何违规计数；优先让计数下降。
3. `check:privacy-contract` / `check:privacy-data-map`：通过。
4. 后端 Jest 与前端 Vitest：新增用例覆盖纯函数；既有用例不回归。
5. CI 全绿（最终以 GitHub Actions 为准）。

## 11. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 控制器/页面文件超限 | 先抽 `ticketWorkflowService`、`TicketConversation`、`TicketEventTimeline`、`TicketUserFilters`、`TicketBulkBar` |
| 事件数组无限增长 | `$slice: -100`；只在真实字段变化时追加 |
| 统计聚合拖慢管理端 | 单次 `$facet`/并行聚合；首响统计限定最近 30 天 |
| URL 同步与 React 状态互相触发 | 只从 URL 读一次初始化；写 URL 用 `replaceState`，不监听 `popstate` 以免覆盖用户输入 |
| WS 广播泄露管理员姓名 | 脱敏放在 `toTicketView`，所有出口共用 |
| 批量操作误伤 | 确认弹窗 + 只对选中 ID + 服务端字段校验 + 返回真实变更计数 |
| 旧客户端不传新参数 | 全部 query/body 字段可选；响应只增字段不删字段 |
