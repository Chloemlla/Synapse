 核心方案

  1. 新增第三方身份表 AccountIdentity
     字段：provider、providerUserId、userId、providerEmail、providerUsername、avatarUrl、linkedAt、
     lastUsedAt、status。
     用唯一索引 { provider, providerUserId } 防止同一个 Google/Linux.do 账号绑定多个本地账号。

  2. 新增账号合并服务 accountMergeService
     当第三方账号已经对应另一个本地用户时，不自动合并，先生成 mergePreview：
      - 源账号：第三方账号当前绑定的本地用户
      - 目标账号：当前登录用户
      - 展示可合并内容数量：TTS 历史、任务、资产、Artifacts、短链、工单、偏好、API Key、工作空间等
      - 展示风险项：管理员/可信用户角色、封停状态、API Key/OAuth Token、邮箱冲突

  3. 绑定流程
      - UserProfile 点击“绑定 Google / Linux.do”
      - 必须先通过现有 /api/admin/user/profile/verify 身份验证
      - 后端发起 provider 授权
      - provider 回调后判断：
          - 未绑定：直接绑定到当前用户
          - 已绑定当前用户：刷新资料
          - 已绑定其他用户：返回合并预览
          - 高风险冲突：要求二次确认或管理员处理

  4. 合并策略
      - 自动迁移：TTS jobs/history/assets、Artifacts、短链、工单、翻译日志、推荐历史
      - 智能合并：用户偏好、推荐记录、工作空间成员，去重并保留更高成员权限，前端允许用户手动确认并修改相关信息
      - 保守处理：API Key、OAuth grant/token、账单事件迁移前展示确认，前端允许用户手动确认并修改相关信息；OAuth refresh token 默认撤销
      - 安全字段不自动覆盖：密码、TOTP、Passkey、角色不从源账号覆盖目标账号
      - 封停账号不能通过合并逃逸：任一账号 suspended 时阻断或进入管理员审核

  5. 前端改造 frontend/src/components/UserProfile.tsx:1502
     把现在的“关联账号”只读行改成“第三方账号”管理区：
      - Google / Linux.do 卡片
      - 状态：已绑定 / 未绑定 / 可合并 / 冲突
      - 操作：绑定、解绑、刷新、查看合并预览
      - 合并确认弹窗：显示迁移项目数量、风险项、最终目标账号
      - 成功后刷新 profile，不切换当前登录账号

  6. 推荐接口设计
      - GET /api/admin/user/profile/linked-accounts
      - POST /api/admin/user/profile/linked-accounts/:provider/start
      - POST /api/auth/google/bind
      - GET|POST /api/auth/linuxdo/callback?intent=bind
      - POST /api/admin/user/profile/linked-accounts/:provider/unlink
      - POST /api/admin/user/profile/account-merge/preview
      - POST /api/admin/user/profile/account-merge/confirm

  7. 实施顺序
      1. 加 AccountIdentity 模型和现有 Linux.do 绑定回填。
      2. 做 linked-accounts 查询，让 UserProfile 先能展示真实绑定状态。
      3. 支持 Google/Linux.do 绑定和解绑。
      4. 做合并预览，不执行迁移。
      5. 做事务合并和审计日志。
      6. 补测试：绑定冲突、重复绑定、合并预览、封停阻断、工作空间成员去重、TTS/短链迁移。

  这个方案的关键点是：绑定是低风险操作，合并是高风险操作，必须可预览、可审计、可阻断。这样后续再接
  GitHub、Microsoft、Discord 也只需要新增 provider adapter，不需要继续改用户表结构。
